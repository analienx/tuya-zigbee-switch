# BSEED Router routing hardening — 2026-10-03

This is the second implementation pass for issue #55, stacked on the shared
hardening PR #61. It adds observability and fixes verified counter-persistence
and management-dispatch defects. It does not replace Telink's native routing
algorithm or establish hardware/fleet acceptance.

## Counter persistence

The pinned V3.7.2.0 driver returns success after failed network frame-counter
writes. The native Router boot caller also ignores that return value, confirmed
by TC32 disassembly on GitHub Actions. Returning an error alone cannot protect
the counter.

A build-local patch verifies the selected sector and latest stored counter
before returning to the native caller. A checksum failure permits one retry
into the other sector, preserving the previously valid sector. The first
successful write into an empty sector is accepted by readback even though the
native handler retains its initial NOT_FOUND status. Loads retain the latest
valid counter without the SDK's large-gap rollback/write. Both save and boot
load reject a counter whose next 1024 reservation would reach the erased-word
sentinel or wrap.

If persistence cannot be verified, the firmware synchronously disables IRQs,
turns radio TX/RX off, stops the watchdog and halts. Relay/GPIO outputs are
preserved. **Buttons, metering, protection processing and other application work
also stop**; this is an exceptional fail-stop, not a degraded operating mode.
The device needs physical recovery after its storage is repaired. It does not
factory-reset itself or repeatedly reboot. The fault is RAM-only and cannot be
queried over Zigbee after radio shutdown.

This protects the audited write/reservation paths. It is not a proof against
arbitrary flash corruption or every power-cut timing: initially absent/corrupt
counter storage can still be indistinguishable from fresh storage to the native
boot logic. Native SDK security behavior outside these patched entry points
remains an audit/hardware boundary. Do not claim complete anti-replay assurance.

The patch applies to native Router and Client because they share the driver.
No sealed legacy image is rebuilt under its old identity.

## Routing and management behavior

Router builds reject power management and receiver-off settings at compile
time. Router descriptors explicitly advertise mains power and continuous
reception. RF power, PA settings, table capacities, retries and link-status
timing remain at their existing values.

ZDP rejects null/short common responses and validates supported request wire
lengths before native dispatch, including bounded cluster lists, bind address
modes, parent child lists and network-update variants. Successful address and
parent responses are checked before the native notification handlers. This is
a bounded guard around supported formats, not a general proof of every opaque
SDK handler against fuzzing.

Mgmt_Rtg reuses the existing sparse-table selector, snapshots the reply address
before buffer reuse, paginates at nine entries (50 bytes), and releases its
request exactly once. Hosted C tests exercise the actual handler, codec and ZDP
dispatch functions with buffer fakes. TC32 builds provide the real SDK ABI gate.

## Diagnostics

Basic cluster read-only octet strings:
- 0xFF10: existing shared-health schema, retained.
- 0xFF11: Router routing snapshot, 48-byte payload, schema 1.
- 0xFF12: native runtime snapshot, both roles, 48-byte payload, schema 1.

Read each attribute individually; combined replies can exceed the conservative
57-byte native APS payload budget. These attributes are not reportable.
Their ZCL value has a one-byte length prefix; offsets below exclude that prefix.
All multi-byte fields are little-endian. SDK counters keep their native widths
and wrap; application counters saturate. Snapshots refresh once per second.
Observed table/buffer peaks are sampled peaks, not allocation-time maxima.
No probes, reports, NVM writes or route mutations are generated by diagnostics.

### Router payload (0xFF11)

| Offset | Field |
|---|---|
| 0 | Schema = 1 |
| 1 | Last raw NWK status, initially 0xFF |
| 2 | Bits 0/1/2: actual MAC Rx-on / node descriptor Rx-on / continuous power mode |
| 3 | Reserved |
| 4–5 | Last NWK-status address, initially 0xFFFF |
| 6–9 | Neighbors, child end devices, neighbor capacity, configured child quota |
| 10–12 | Route entries, active routes, route capacity |
| 13–15 | Packet buffers used, capacity, observed peak |
| 16–19 | Uptime milliseconds |
| 20–23 | NWK-status callback count (saturating u32) |
| 24–25 | Relayed unicasts (SDK u16) |
| 26–27 | Route discoveries initiated (SDK u16) |
| 28–29 | MAC unicast retries (SDK u16) |
| 30–31 | MAC unicast failures (SDK u16) |
| 32–33 | Packet allocation failures (SDK u16) |
| 34–35 | PHY-to-MAC queue limit reached (SDK u16) |
| 36–43 | Neighbor added / removed / stale / child moved (four SDK u16) |
| 44–47 | MAC receive CRC failures (SDK u32) |

The configured child quota is not a claim about effective native NIB admission.
There is no inferred occupancy for opaque MAC/APS queues.

### Runtime payload (0xFF12)

| Offset | Field |
|---|---|
| 0 | Schema = 1 |
| 1 | Actual MAC Rx-on |
| 2 | Reserved |
| 3 | Fatal counter status (RAM only; radio is off on fatal failure) |
| 4–7 | Maximum interval between stack-service calls, microseconds |
| 8–11 | Maximum instrumented flash write/erase IRQ-masked interval, microseconds |
| 12–15 | Instrumented flash operation count (saturating u32) |
| 16–19 | Counter fail-stop count (saturating u32) |
| 20–23 | Counter retry count (saturating u32) |
| 24–27 | Current native outgoing network frame counter |
| 28–31 | MAC CCA failures (SDK u32) |
| 32–35 | MAC received unicasts (SDK u32) |
| 36–39 | MAC transmitted unicasts (SDK u32) |
| 40–41 | Last native LQI / signed RSSI |
| 42–43 | Observed neighbor / route peak (Router; zero on Client) |
| 44–47 | Uptime milliseconds |

The flash hook runs from RAM, uses only scalar operations and records from IRQ
disable through flash completion. It measures write/erase service gaps; it does
not make them interruptible or include every flash-read mask interval. The
stack-service maximum also includes other main-loop work and scheduler delays.
The 32-bit hardware tick subtraction handles one wrap; gaps spanning multiple
tick wraps are outside this metric.

## Candidates and acceptance

Fresh board-wide identities allocated on GitHub Actions before firmware edits:
- PM Router r12 / Client cli14: 0x12053019, image types 43556 / 65024.
- Non-PM Router r12 / Client c9: 0x11023016, image types 43555 / 65026.
- Build date pinned to 20261003.

Required offline evidence is from the exact candidate SHA on GitHub-hosted
runners: full tests and lint, native Router/Client compilation, shared PM
`make bseed/pm-matrix`, non-PM role matrix, reproducibility and four-identity
sealing. Router lanes also extract actual initialized capacities and linker
RAM margin from their ELF and verify the flash hook resides in RAM. Static
margin beyond the linker-reserved minimum stack is not runtime stack proof.

After merge, separate live authorization and the repository OTA gates are
required for any canary. Hardware work must test actual child parenting,
bursty forwarding, route/neighbor turnover, coordinator restart, sleepy-child
retention, flash service gaps, counter continuity through controlled power cuts,
and successful recovery from storage faults with a safe relay fixture.
Measure delivery, retries, latency and table pressure before changing table
sizes, RF power or retry policy. These measurements are necessary before
calling a Router best in class.
