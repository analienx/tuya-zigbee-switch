# HifiLeft BSEED PM Client: manually tested configuration (2026-09-20)

**Scope: one-device manual canary, not a general firmware release or an automated E2E pass.**

- Device: `LivingRoomSocketHifiLeft`, IEEE `0xa4c138da1333dc70`; identified in live Zigbee2MQTT as `b28wrpvx` / `TS011F-BS-PM`, mains-powered `EndDevice`, successfully interviewed.
- Installed device software: `1.2.5-bseedcli6` (PM Client); the existing Client image is unchanged by the converter/reporting work in PRs #47 and #49. This canary identifies the **combination** of firmware and Zigbee2MQTT configuration rather than asserting that CLI6 alone repaired spontaneous updates.
- Zigbee2MQTT: BSEED external converter from PR #49; supported PM model maps endpoint-1 `power`, `current`, `voltage`, `energy` to unsuffixed standard MQTT properties, while endpoint 2 remains the relay. Converter also bounds other PM report maximums when configured: current/voltage 300 s and energy 600 s.
- Live active-power reporting on endpoint 1: `haElectricalMeasurement.activePower`, minimum 10 s, maximum 60 s, reportable change 5 W; coordinator binding verified during reporting configuration. The 60-second maximum was verified by a raw device-originated ZCL `attributeReport(activePower=0)` and corresponding MQTT update, without a read.
- User-reported manual acceptance: a connected load produced a nonzero power reading and after the load was removed the reported value returned to **0 W**. This addresses the originally observed stale ~25 W reading in this one device under its current live setup.

**Not established by the manual report:** timestamped load-to-zero latency, an independently verified preceding loaded ZCL `attributeReport`, unattended repeated transitions, HA-state correlation, Client rejoin/OTA resilience, or validation of other physical sockets. `tests/live_bseed_pm_metering.py` remains the separate automated hardware release gate; its pass status is **pending**. Do not describe this one manual canary as a production-wide/golden Client release.

**HifiLeft direct conversion history and KitchenSocketLeft migration boundary:** HifiLeft's stock `_TZ3000_b28wrpvx` → PM Client migration was reported as **direct**, without an intermediate custom Router firmware flash. The locally prepared `pm-stock-to-client-cli4-CANDIDATE.ota` is a stock-facing Client wrapper (stock image type `54179`, outer version `0xFFFFFFFF`) around the same Client payload as its normal custom image type `65024`. Its local manifest says **offline verified only, not flashed or hardware-tested**; do not cite that manifest alone as proof of the precise file used in HifiLeft's historical OTA. HifiLeft later received custom Client updates and now runs `cli6`.

KitchenSocketLeft is stock `_TZ3000_b28wrpvx` / `TS011F` Router (IEEE `0xa4c138241e3de538`), not an already-custom PM Router. **Two possible migration routes exist:** (1) exact stock-facing Client wrapper → custom PM Client in one OTA, as with the reported HifiLeft migration; or (2) published stock `from_tuya` PM Router → separately validated custom Router `from-router.ota` Client transition. The ordinary Client build's `stockConversion: false` means it does not **publish** a stock conversion package, not that a direct Client package is technically impossible. The existing `from-router.ota` must not be offered to stock TS011F. Neither route is authorized just by HifiLeft's manual metering test: verify correct target and binary, backup/recovery implications, radio/interview/rejoin and functional acceptance before replacing KitchenSocketLeft's pristine stock firmware. No KitchenSocketLeft OTA was started as part of this documentation correction.

**CLI6 source synchronization:** `make_scripts/build_bseed_mains_client.sh` pins the PM Client build ID `1.2.5-bseedcli6` and OTA version `0x1205300C`. `src/telink/hal/zigbee_network.c` refreshes the parent lease via a 60-second MAC poll on join/rejoin, scoped to `BSEED_MAINS_CLIENT`. Non-PM and TS0726 Client version pins remain unchanged. Source tests do not prove byte-for-byte equivalence to the image installed on HifiLeft.
